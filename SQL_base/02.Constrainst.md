# 📖 Constraints

**Constraints** — это ограничения, которые помогают базе данных хранить только корректные данные.

Основные ограничения:

- PRIMARY KEY
- FOREIGN KEY
- NOT NULL
- UNIQUE
- DEFAULT
- CHECK

---

# 🔑 PRIMARY KEY

## Определение

**PRIMARY KEY** — это поле, которое уникально идентифицирует каждую строку таблицы.

Каждая таблица имеет только **один PRIMARY KEY**.

---

## Свойства

- Уникальный.
- Не может быть NULL.
- Не повторяется.
- Обычно называется `id`.

---

## Пример

```sql
CREATE TABLE Customers (
    id INT PRIMARY KEY,
    name VARCHAR(100)
);
```

---

## Для чего нужен

По PRIMARY KEY база данных всегда может найти одну конкретную запись.

Например:

```text
id = 15
```

означает одного конкретного пользователя.

---

# 🌍 Реальные проекты

Практически во всех проектах используется поле:

```sql
id INT PRIMARY KEY
```

Даже если существуют другие уникальные поля (email, VIN, номер паспорта).

---

# 🔗 FOREIGN KEY

## Определение

**FOREIGN KEY** — это поле, которое ссылается на PRIMARY KEY другой таблицы.

Именно FOREIGN KEY связывает таблицы между собой.

---

## Пример

```sql
CREATE TABLE Orders (

    id INT PRIMARY KEY,

    customer_id INT,

    FOREIGN KEY (customer_id)
    REFERENCES Customers(id)

);
```

---

## Что означает REFERENCES

```sql
REFERENCES Customers(id)
```

означает:

Поле `customer_id` может содержать только такие значения, которые существуют в `Customers.id`.

Если такого пользователя нет — база данных выдаст ошибку.

---

# 📦 Пример интернет-магазина

## Customers

```text
id (PK)
name
email
```

---

## Products

```text
id (PK)
name
price
```

---

## Orders

```text
id (PK)

customer_id (FK)

product_id (FK)
```

---

# Как это работает

```
Customers
----------
id (PK)

        ↑
        │
customer_id (FK)

Orders
----------
id (PK)
customer_id (FK)
product_id (FK)

        │
        ↓

Products
----------
id (PK)
```

Orders хранит только ссылки на пользователя и товар.

---

# Почему не хранят имя пользователя?

❌ Плохо

```text
Orders

Oleksii
Oleksii
Oleksii
Oleksii
```

Если пользователь поменяет имя — придется менять сотни записей.

---

✅ Правильно

```text
Orders

customer_id = 1
customer_id = 1
customer_id = 1
```

Имя хранится только в таблице Customers.

---

# Важно понимать

PRIMARY KEY отвечает на вопрос:

> Кто это?

FOREIGN KEY отвечает на вопрос:

> К кому относится эта запись?

---

# Что нужно знать наизусть

## PRIMARY KEY

- уникальный идентификатор строки;
- один PRIMARY KEY на таблицу;
- не может быть NULL;
- не повторяется.

---

## FOREIGN KEY

- ссылается на PRIMARY KEY другой таблицы;
- связывает таблицы;
- защищает данные от некорректных связей;
- может повторяться много раз.

---

# Что нужно понимать

✅ Один пользователь может иметь много заказов.

Поэтому:

```text
customer_id = 1
customer_id = 1
customer_id = 1
```

— это НЕ дублирование данных.

Это три разных заказа одного пользователя.

---

# Самое главное запомнить

> PRIMARY KEY — это уникальный идентификатор записи.

> FOREIGN KEY — это ссылка на PRIMARY KEY другой таблицы.

> Благодаря FOREIGN KEY таблицы связываются между собой.

---

# 📌 Мини-конспект

```
PRIMARY KEY
↓
Уникально определяет запись.

FOREIGN KEY
↓
Ссылается на PRIMARY KEY другой таблицы.

Customers
        ↑
        │
Orders
        │
        ↓
Products
```
